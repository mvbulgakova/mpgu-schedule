# Проверка позиции в конкурсных списках МПГУ — дизайн (подпроект B)

**Дата:** 2026-07-01
**Статус:** утверждён к реализации
**Подпроект B** помощника абитуриента. Опирается на инфраструктуру подпроекта A
(бот `scraper/telegram_bot.py`, пакет `scraper/abitur/`) и общий паттерн проекта
(fetcher + parser + `GitStorage` + workflow + data-ветка + чтение ботом через jsDelivr).

## Цель

Абитуриент присылает боту свой **уникальный код** (личный номер заявления) — бот
показывает все направления МПГУ, где этот код есть в конкурсных списках: позицию, сумму
конкурсных баллов, приоритет, наличие согласия, основание БВИ, статус рассмотрения, и время
последнего обновления данных.

## Разведка источника (проведена 2026-07-01)

Списки живут на `https://epk25.mpgu.su`, **рендерятся сервером** (JS не нужен; теги в
ВЕРХНЕМ регистре — похоже экспорт из таблицы). Навигация в 3 уровня по curl:

1. `/competitive-list/structural?educationLevel=<lvl>` — карточки подразделений/филиалов со
   ссылками на уровень ниже. Значения `<lvl>`: `basic_higher_education`, `bahelor` (пустой
   легаси), `specialist`, `specialized_higher_education`, `magistracy`,
   `secondary_vocational_education`, `postgraduate`.
2. `/competitive-list/direction?educationLevel=<lvl>&university=<u>&structuralUnit=<n>` —
   список направлений со ссылками `view?code=<code>` (у филиалов параметр `structuralUnit`
   может отсутствовать; `university` например `main_university`, `anapa_branch`, `college`).
3. `/competitive-list/view?code=<code>` — сам конкурсный список. Таблица (uppercase HTML),
   колонки: **№ · Уникальный код · Наличие согласия на зачисление · ПЗ · ОВП · ВПП ·
   Основание приёма БВИ · Сумма конкурсных баллов · Сумма баллов за ВИ · ВИ1 · ВИ2 · ВИ3 ·
   ИД · ПП · Информация о рассмотрении заявления · Причина отказа · Высший проходной
   приоритет**. Абитуриент опознаётся по «Уникальному коду» (не СНИЛС) — публично и
   приватно-безопасно.

## Архитектура (подтверждена)

Живой поиск на каждый запрос невозможен: чтобы найти код, надо обойти ВСЕ списки. Поэтому —
как с расписанием: **периодический скрейп → индекс в data-ветке → бот читает через jsDelivr.**

## Компоненты

### 1. Фетчер обхода — `scraper/fetchers/lists_fetcher.py`

Обходит epk25 по трём уровням и собирает все `view?code=<code>` вместе с контекстом (уровень,
университет/филиал, подразделение, название направления). Использует существующий паттерн
`site_fetcher`/aiohttp + tenacity (ретраи). Вежливость: небольшой конкурентный лимит и паузы,
User-Agent. Возвращает список задач `{code, level, university, subdivision, direction, url}`.

### 2. Парсер списка — `scraper/parsers/competitive_list_parser.py`

Вход: HTML страницы `view`. Через BeautifulSoup (lxml) читает таблицу (bs4 нормализует
регистр тегов). Возвращает: метаданные списка (название направления, code) + строки:
`{position:int, unique_code:str, consent:bool, priority_pz, priority_ovp, priority_vpp,
bvi:bool, score_total:int, score_vi:int, vi:[...], id_points:int, status:str, reject_reason}`.
Пустые ячейки (`<SPAN></SPAN>`) → None/False. Чистый, изолированно тестируемый (фикстура —
сохранённый HTML одного списка).

### 3. Построение индекса — `scraper/build_lists_index.py`

Соединяет фетчер и парсер, строит индекс, пишет через `GitStorage`:

```json
{
  "updated_at": "2026-07-01T20:00:00+03:00",
  "campaign": "2026",
  "lists": {
    "000000672": {"direction": "44.03.01 ... История", "level": "basic_higher_education",
                  "university": "main_university", "subdivision": "...",
                  "url": "https://epk25.mpgu.su/competitive-list/view?code=000000672",
                  "count": 123}
  },
  "codes": {
    "1281839": [
      {"list": "000000672", "position": 1, "score_total": 290, "consent": false,
       "priority_pz": 28, "bvi": false, "status": "На рассмотрении"}
    ]
  }
}
```

Хранение на data-ветке: `admissions/lists_index.json`. Если файл станет слишком большим для
одного jsDelivr-запроса — шардировать `codes` по первым цифрам кода
(`admissions/by_code/<prefix>.json`) + лёгкий `admissions/lists_meta.json`; для MVP — один
файл, шардирование отмечено как расширение.

### 4. Workflow — `.github/workflows/fetch-lists.yml`

По образцу `fetch-exams.yml`: checkout кода (main) + data-ветки в `data/`, Python, установка
зависимостей (`aiohttp beautifulsoup4 lxml tenacity`), запуск `python -m scraper.build_lists_index`,
`GitStorage.commit_and_push`. Расписание — во время кампании часто (например каждые 2–3 часа);
`workflow_dispatch` для ручного прогона. Идёт мимо приёмной кампании только в её сроки.

### 5. Интеграция в бот — `scraper/abitur/lists.py` + правки `telegram_bot.py`

- `scraper/abitur/lists.py`: `fetch_index()` — тянет `admissions/lists_index.json` с jsDelivr
  (`DATA_BASE`, как раньше делал бот расписания); `lookup(index, code) -> list[entry]`;
  `format_positions(index, code) -> str` — человекочитаемый ответ (по направлениям: позиция,
  сумма баллов, приоритет, согласие, БВИ, статус) + `updated_at` + ссылка на официальный
  список. Кэш индекса в памяти на несколько минут (бот живёт окнами).
- Бот: команда `/spisok` (и кнопка «🔎 Мои списки» в меню). Поток: `/spisok` → «пришлите ваш
  уникальный код»; ставим лёгкий флаг `AWAITING_CODE[chat_id]` (отдельный от состояния
  калькулятора). Следующее числовое сообщение при активном флаге → поиск по индексу.
  `/spisok <код>` — тоже принимается сразу. **Конфликт с вводом часов волонтёрства решается
  приоритетом:** если активна сессия калькулятора на шаге ACHIEVE — число трактуется как часы;
  иначе если активен `AWAITING_CODE` — как код списка.
- Если код не найден: «код не найден — проверьте номер или загляните в официальные списки»
  + ссылка + напоминание, что данные обновляются периодически (возможна задержка).

### 6. Приватность и дисклеймеры

Уникальный код — публичный идентификатор из открытых списков; СНИЛС/ФИО бот не запрашивает и
не хранит. Ответ всегда содержит: время обновления индекса, ссылку на официальный список, и
оговорку «данные предварительные, ориентируйтесь на официальные списки и ЛК на Госуслугах».

## Тесты

- `competitive_list_parser` — на сохранённой фикстуре HTML одного списка: число строк,
  корректный разбор позиций/кодов/баллов/согласия/статуса, обработка пустых ячеек.
- `build_lists_index` — на моках фетчера/парсера: сборка индекса, дедуп, форма JSON.
- `scraper/abitur/lists.py` — `lookup`/`format_positions` на синтетическом индексе (найдено /
  не найдено; несколько направлений; наличие `updated_at` и ссылки).
- Бот: маршрутизация `/spisok` и `AWAITING_CODE`; приоритет «часы волонтёрства vs код списка».
- Фетчер/сеть в юнит-тестах не вызывается (моки).

## Риски и смягчения

- **Хрупкость разметки портала** → парсер терпимый (пустые ячейки, отсутствующие колонки),
  фикстура в тестах; при смене формата — падение теста подсветит.
- **Объём/скорость обхода** (сотни направлений) → умеренная конкурентность + ретраи; частота
  workflow разумная; кэш индекса в боте.
- **Размер индекса для CDN** → при необходимости шардирование по префиксу кода.
- **Неполнота/задержка данных** → явный `updated_at` и дисклеймер со ссылкой на официал.
- **Приватность** → только публичный уникальный код; без СНИЛС/ФИО.

## Критерии готовности

- `/spisok <код>` и поток через кнопку показывают все направления абитуриента с позицией,
  баллами, приоритетом, согласием, статусом и временем обновления; несуществующий код —
  корректное сообщение со ссылкой.
- Индекс собирается workflow и коммитится в data-ветку; бот читает его через jsDelivr.
- Ввод часов волонтёрства в калькуляторе не конфликтует с вводом кода списка.
- Парсер и логика бота покрыты юнит-тестами; существующие тесты не сломаны.
