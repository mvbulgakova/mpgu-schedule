# Прогноз проходного балла + квоты + 2021 — дизайн

Дата: 2026-07-21. Статус: утверждён к реализации (согласовано с @soldat_olovyanniy).

## Задача

Абитуриент хочет понимать не только «где я сейчас», но и **примерный проходной
балл** программы на 2026 год. Плюс достроить историю: добавить 2021 и
подтянуть квоты.

## Область (scope)

1. **2021 в историю** — тем же способом, что 2022–2025 (списки зачисления).
2. **Квоты** — распарсить квотные секции зачисления; квотные МЕСТА уже
   используются для «общий = КЦП − квоты». Квотные проходные складываем в
   `history.json` как отдельные записи, но **абитуриенту не показываем** (они
   сильно ниже общего конкурса, релевантны единицам, легко принять за общий).
   Можно упомянуть одной строкой «по квотам проходной ниже».
3. **Примерный проходной-2026** — прогноз на основе (а) истории 2021–2025 и
   (б) текущей картины конкурса (места + распределение баллов + симуляция по
   согласиям). Показываем **диапазоном** с явной пометкой «прогноз, не
   гарантия».

## Не входит (non-goals)

- Магистратура/СПО в прогнозе (только базовый бакалавриат/специалитет, где есть
  и история, и живые списки).
- Точное «одно число» проходного. Осознанно избегаем ложной точности.
- Отдельный показ квотных проходных абитуриенту (данные копим, показ — потом).

## Примерный проходной-2026: алгоритм

Считаем **только для общих бюджетных списков** (`general=True`, есть `places`).
Три РЕАЛЬНЫХ числа, каждое честно объяснено, без «чёрного ящика»:

Обозначения на список:
- `G` — места общего конкурса = `places − quota_places` (уже есть,
  `_general_seats`).
- `totals` — баллы всех подавших, по убыванию (уже есть в `lists_meta`).
- Симуляция отложенного зачисления (уже есть) → множество зачисленных.

1. **`cap` — «по местам и баллам» (верхний сценарий).**
   `cap = totals[G-1]` (G-й сверху балл среди подавших). Это проходной, ЕСЛИ
   места займут G сильнейших из уже подавших. Прямо «места + распределение».
   ВАЖНО: это ВЕРХНЯЯ граница — часть сильных уходит в другие программы/вузы,
   поэтому реальный проходной обычно НИЖЕ `cap` (пример: соц.психология
   `cap≈270`, факт-2025 = 244). Значит `cap` НЕЛЬЗЯ подавать как «проходной».

2. **`sim` — «по согласиям сейчас» (нижняя граница сегодня).**
   Минимальный балл среди зачисленных в симуляции (только согласившиеся).
   Считаем на этапе сборки, кладём в `lists_meta` как `sim_cutoff`. Растёт к
   5 августа. Сейчас занижен.

3. **`hist` — история 2021–2025** (последние до 3 лет из `history.json`).
   Лучший одиночный предиктор финального числа (там уже «осевший» проходной).

**Итоговый показ (диапазон, история — якорь):**
```
📊 Примерный проходной-2026: ориентир ~{lo}–{hi}
   • В прошлые годы: 2023: X, 2024: Y, 2025: Z
   • Сейчас по согласиям проходят от ~{sim} (↑ вырастет к 5 августа)
   • Топ-{G} баллов среди подавших начинается с ~{cap}
     (если сильнейшие останутся — но часть уходит в другие вузы)
   ⚠️ Прогноз, не гарантия. Точный проходной-2026 — после зачисления.
```
где диапазон `[lo, hi]`:
- `lo = min(hist_recent)` если есть история, иначе `sim`;
- `hi = max(max(hist_recent), sim)` — не ниже свежей истории и не ниже текущего
  живого сигнала по согласиям; `cap` в диапазон НЕ берём (он завышает), но
  показываем справочно строкой.
- Если история отсутствует (нет матча) — прогноз диапазоном не даём, показываем
  только живые `sim`/`cap` со всеми оговорками (не выдумываем).

Обоснование выбора границ: история — где проходной реально садился; `sim` —
живой пол этого года. Диапазон между ними честен и не завышен `cap`-ом. Если
`sim` уже выше прошлогоднего максимума — значит год идёт горячее, `hi` это
поймает.

## Где показываем

- `/shansy` (подбор по баллам, `shansy.format_answer`) — под каждой программой,
  где есть общий бюджетный список: строка прогноза.
- `/spisok` подробный (`lists.format_positions`) — в блоке общего конкурса.
- Компактный `/spisok` (`format_positions_short`) — НЕ трогаем (там и так
  плотно); прогноз только в «Подробнее».

## Изоляция компонентов

- `scraper/abitur/prediction.py` (новый, чистый): `predict_range(hist, sim,
  cap, G) -> dict | None` и `format_prediction(...) -> str`. Без сети, без
  чтения файлов — только числа на вход. Полностью юнит-тестируемо.
- `build_lists_index`: добавить `sim_cutoff` (и `cap`) в `lists_meta` на этапе
  сборки — там уже есть симуляция и `totals`.
- Показ (`shansy`, `lists`) вызывает `prediction.format_prediction`.

## Тестирование

- `prediction.predict_range`: границы диапазона при (есть/нет истории), когда
  `sim` выше истории (горячий год), когда `cap`<истории (слабый год), пустые
  входы → None.
- `enrollment_parser`: квотные секции получают `quota_kind`, общий конкурс — без
  метки; квотные не попадают в общий `history`.
- `build_lists_index`: `sim_cutoff`/`cap` пишутся для общих бюджетных списков и
  отсутствуют для платных/квотных.
- Реперы: прогноз для соц.психологии развития разумен (диапазон охватывает
  244–266, не улетает в `cap≈270`).

## Риски

- «Ошибаться нельзя»: главный риск — ложная точность и завышение `cap`-ом.
  Снимаем: показ диапазоном, история-якорь, `cap` только справочно с оговоркой.
- Прогноз без истории (нематч программы) — не выдумываем, показываем только
  живые сигналы.
- Бэктест прогноза невозможен (нет исторических внутрикампанийных снимков
  распределения) — поэтому осознанно консервативны и прозрачны в формулировках.
