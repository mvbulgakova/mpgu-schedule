# AI-помощник абитуриента в Telegram-боте МПГУ — дизайн

**Дата:** 2026-06-30
**Статус:** утверждён к реализации
**Подпроект A** из декомпозиции «помощник абитуриента» (A — FAQ/AI, B — конкурсные
списки онлайн; B проектируется отдельным спеком после A).

## Цель

Сейчас `scraper/telegram_bot.py` умеет одно: поиск группы по коду → пары на сегодня.
Идёт приёмная кампания. Нужно, чтобы тот же бот отвечал абитуриентам на вопросы о
поступлении (сроки, документы, общежитие, внутренние испытания, контакты, где смотреть
списки) — точно, без выдумок, со ссылками на официальные источники.

Аудитория: поступающие и их родители. Канал: тот же Telegram-бот.

## Не-цели (вне этого спека)

- Парсинг конкурсных списков с `epk25.mpgu.su` и проверка позиции абитуриента —
  это подпроект B (бот лишь даёт ссылку на списки и объясняет, как их читать).
- Изменение логики расписания — ветка расписания не трогается.
- Векторная база / эмбеддинги — не нужны (см. «Архитектурное решение»).

## Архитектурное решение: KB-in-prompt (RAG-lite)

База знаний по приёмке маленькая (одна официальная страница FAQ + горстка фактов).
Она целиком влезает в системный промпт, поэтому вместо векторного RAG используем
заземление всего KB в `system` с prompt caching. Проще, дешевле, надёжнее против
галлюцинаций.

### 2. Маршрутизация в `handle()`

`handle(text)` получает развилку (порядок проверок важен):

1. `/start`, `/help` — обновлённая справка: умею и расписание (код группы), и вопросы
   по поступлению (`/abitur`).
2. `/abitur` (или ключевые слова темы) — меню Telegram-кнопок частых тем:
   **Сроки · Документы · Общежитие · Списки · Внутренние испытания · Контакты**.
   Нажатие → **детерминированный** ответ из KB (готовый текст + ссылка), без LLM.
3. Иначе если текст похож на **код группы** (текущая `search_key`/regex, ≥3 симв.,
   матч по `meta/groups.json`) → ветка расписания, как сейчас (не меняется).
4. Иначе (свободный вопрос) → **AI-ответ**, заземлённый на KB (см. ниже).

Детерминированные кнопки закрывают топ-вопросы мгновенно и без токенов; AI — длинный
хвост формулировок.

Маршрутизация выделяется в чистые функции (`route(text) -> intent`,
`faq_button_answer(topic) -> str`) для изолированного юнит-тестирования без сети.

### 3. AI-ответ — `scraper/abitur/llm.py`

- Один вызов `client.messages.create` (Anthropic SDK, Python).
- **Модель:** `claude-haiku-4-5`.
- **Без** extended thinking и **без** `output_config.effort` (Haiku 4.5 не поддерживает
  `effort` — вернёт ошибку). Обычный `system` + один `user`-месседж.
- `system` = строгая инструкция + весь текст `knowledge.md`, на последнем блоке
  `cache_control: {"type": "ephemeral"}` (стабильный префикс кэшируется → дёшево при
  потоке вопросов).
- `max_tokens` ~512 (ответы короткие).
- Текст вопроса пользователя — в `user`.

**Системный промпт (anti-hallucination, тема чувствительная):**
- отвечать ТОЛЬКО на основе предоставленной базы знаний;
- НЕ выдумывать даты, числа, проходные баллы, перечни документов; если данных в базе
  нет — честно сказать «точно подскажет приёмная комиссия», дать её контакты и
  релевантную официальную ссылку;
- всегда добавлять официальную ссылку под ответом;
- кратко, по-русски, дружелюбно; не давать юридических/медицинских гарантий;
- если вопрос про расписание/код группы — подсказать прислать код группы.

**Обработка ответа/ошибок:** парсить `response.content` (блок `text`); ловить типизированные
исключения SDK (`RateLimitError`, `APIStatusError`, `APIConnectionError`) → отдавать
дружелюбный фолбэк с контактами приёмки (бот не падает).

### 4. Деплой / секреты

- Новый секрет репозитория `ANTHROPIC_API_KEY`, проброс в `bot-poll.yml`.
- **Деградация без ключа:** если `ANTHROPIC_API_KEY` не задан, AI-ветка отключается, а
  расписание и детерминированные FAQ-кнопки работают (как уже сделано с `BOT_TOKEN`).
  Свободный вопрос без ключа → сообщение «спросите кнопками /abitur или у приёмной
  комиссии» + контакты.
- Лёгкие guard'ы: лимит длины входящего сообщения (напр. 1000 симв.); простой
  in-memory rate-limit на `chat_id` (напр. N запросов/мин) против абуза/расходов.

### 5. Тесты

- Расширить `--selftest`: проверка `route()` (код группы vs FAQ-кнопка vs свободный
  вопрос), детерминированных ответов кнопок (текст содержит ожидаемую ссылку/факт).
- LLM-ветка тестируется с заглушкой (мок `messages.create`) — без реального вызова API;
  проверяем сборку `system` (KB присутствует, есть anti-hallucination инструкции,
  `cache_control` проставлен) и обработку ошибок (фолбэк с контактами).
- Поведение деградации без `ANTHROPIC_API_KEY`.

## Потоки данных

- KB: репозиторий (feature-ветка) → checkout воркфлоу → читается ботом локально.
- Расписание: data-ветка через jsDelivr (без изменений).
- AI: вопрос пользователя + KB-в-`system` → Anthropic API (Haiku 4.5) → текст → Telegram.

## Риски и смягчения

- **Галлюцинации в чувствительной теме** → строгий заземлённый промпт + KB фиксирует
  ловушки (проходной балл); вне KB → контакты приёмки, без выдумок.
- **Расходы на API** → Haiku 4.5 + prompt caching на KB + детерминированные кнопки на
  топ-вопросы + rate-limit.
- **Устаревание фактов** (даты кампании) → KB версионируется, с датой актуальности;
  обновляется правкой одного файла.
- **Отсутствие ключа/сбой API** → graceful degradation, бот не падает.

## Критерии готовности

- Код группы по-прежнему отдаёт расписание (регресс не допускается).
- `/abitur` показывает меню; кнопки дают корректные факты + ссылки из KB.
- Свободный вопрос по поступлению получает заземлённый ответ со ссылкой; вопрос вне KB
  → контакты приёмки без выдуманных деталей.
- Без `ANTHROPIC_API_KEY` бот стартует зелёным, расписание и кнопки работают.
- Тесты `--selftest` и юнит-тесты проходят.
