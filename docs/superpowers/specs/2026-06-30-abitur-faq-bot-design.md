# AI-помощник абитуриента МПГУ в Telegram — дизайн

**Дата:** 2026-06-30
**Статус:** утверждён к реализации
**Подпроект A** из декомпозиции «помощник абитуриента». Подпроект B — онлайн-проверка
позиции в конкурсных списках с `epk25.mpgu.su` — проектируется отдельным спеком после A.

## Цель и решение по охвату

`scraper/telegram_bot.py` сейчас — бот расписания (поиск группы по коду → пары).
**Решение пользователя: бот становится чисто абитуриентским.** Логика расписания и
кодов групп из бота убирается. Парсеры/данные расписания (`scraper/parsers/*`, data-ветка,
`app/`) **остаются в репозитории** (не удаляются), просто не подключены к этому боту.

Бот помогает поступающим в приёмную кампанию 2026/27: отвечает на вопросы о поступлении
и считает дополнительные баллы за индивидуальные достижения. Точно, без выдумок, со
ссылками на официальные источники МПГУ.

Аудитория: поступающие и родители. Канал: Telegram (long-polling в GitHub Actions).

## Не-цели

- Парсинг конкурсных списков и проверка позиции абитуриента — подпроект B.
- Сохранение логики расписания **в этом боте** (она выносится, но не удаляется из репо).
- Векторный RAG/эмбеддинги — не нужны (KB влезает в системный промпт).

## Архитектура

Два независимых функциональных блока поверх общего бота:
1. **FAQ-помощник** — KB-in-prompt (RAG-lite): курируемая база знаний целиком в `system`,
   кэшируется; ответ моделью строго по KB. Детерминированные кнопки тем для топ-вопросов.
2. **Калькулятор доп. баллов** — полностью детерминированный пошаговый диалог на
   inline-кнопках; суммирование и потолок считаются в коде. **LLM в расчёте не участвует.**

## Компонент 1. База знаний — `scraper/abitur/knowledge.md`

Человекочитаемый Markdown в репозитории (feature-ветка). С датой актуальности сверху.
Воркфлоу выкладывает при checkout — боту не нужна сеть. Разделы:

- **Уровни (федеральный пилот):** базовое высшее образование (БВО) — основной уровень,
  4–6 лет, вместо бакалавриата/специалитета; специализированное высшее (СПВО) и
  магистратура — углублённая подготовка, 1–3 года. Бакалавриат/специалитет/магистратура
  ещё существуют параллельно в переходный период.
- **Кто сдаёт внутренние ВИ вместо ЕГЭ:** выпускники колледжей/СПО, лица с инвалидностью,
  иностранные граждане, лица с имеющимся ВО. Формат — письменно, в т.ч. дистанционно.
- **ДВИ (дополнительные вступительные, творческие/профессиональные):** требуются на
  творческие направления (журналистика, физкультура, музыка, ИЗО, дизайн). На обычный
  бакалавриат ДВИ нет — приём по ЕГЭ. Все ВИ/ДВИ на 1 курс БВО — до 25 июля.
- **Минимальные баллы и перечень ВИ по направлениям** — ссылка на `pk26_perechen` и
  основные Правила приёма (конкретные цифры там; бот не дублирует, а направляет).
- **Сроки:** очная форма — приём документов 9 календарных дней после объявления
  результатов ЕГЭ; заочная — до 4 сентября; зачисление по квотам/БВИ — 30 июля; основной
  этап (общие основания) — 8 августа; справка 086/у (педагогические 44.xx) — до 25 июля;
  договор и оплата на платном — до 27 августа.
- **Особые права и квоты:** БВИ (победители/призёры олимпиад); отдельная квота, целевая
  квота, особая квота (в т.ч. для участников СВО и их детей); преимущественное право —
  ссылка на Приложение 6 / `pk26_uslovia-osobye-prava.pdf`.
- **Целевое обучение:** через платформу «Работа России»/Госуслуги; целевая квота (напр.
  ≥20% мест на «Прикладной информатике»); на целевой квоте потолок ИД выше (+5).
- **Индивидуальные достижения (краткий обзор + отсылка к калькулятору):** перечень и
  потолки (см. компонент 2); подробный расчёт — командой `/bally`.
- **Документы / способы подачи:** онлайн `https://mpgu.su/podat-dokumenty-onlajn/`,

## Компонент 2. Калькулятор доп. баллов

### 2.1. Данные правил — `scraper/abitur/achievements.py` (или `.json`)

Машиночитаемая структура баллов из раздела 9 Правил приёма и Приложения 7. Единый источник
истины для калькулятора. Кодирует:

- **Уровни:** `base` (БВО/бакалавриат/специалитет) и `spec` (СПВО/магистратура) — наборы
  достижений и баллы различаются.
- **Признак педагогического направления** (44.xx) — влияет на баллы за психолого-
  педагогическое волонтёрство.
- **Спортивные (берётся ОДНО, максимальное):** чемпион/призёр ОИ и приравненные — 10;
  чемпион/призёр мира/Европы (не-олимпийские) — 10; МС — 8; КМС — 6; ГТО золото — 5,
  серебро/бронза — 4 (однократно).
- **Документ об образовании с отличием** (аттестат/диплом с отличием/медаль) — 10
  (для `spec` — диплом ВО с отличием — 10).
- **Олимпиады школьников / региональный этап ВсОШ / перечневые олимпиады:** победитель 10,
  призёр 5. Абилимпикс — 10. СВО/добровольческие формирования — 10.
- **Волонтёрство (многоуровневое, по уровню и направлению):**
  - `base`, все направления: ≥100ч=2, ≥200ч=3, ≥300ч=4;
  - `base`, психолого-пед (44.03.xx): ≥100ч=6, ≥200ч=8, ≥300ч=10;
  - `spec`, все направления: ≥300ч=4, ≥400ч=5, ≥500ч=6;
  - `spec`, психолого-пед (44.04.xx): ≥100ч=8, ≥200ч=9, ≥300ч=10.
  Берётся одна, максимальная подходящая ступень.
- **ДО в области искусств / физкультуры (по профилю)** — 10.
- **Именные конкурсы МПГУ из Приложения 7** (Проект по педагогике, Педагогическое будущее
  России, Интеллектуальный мегаполис. Потенциал, Диктант Победы, Без срока давности и др.) —
  победитель/призёр/участник по таблице (часто 10/5/2 или 10/8/6/4).
- **Для `spec` дополнительно:** публикации, патенты, ФИЭБ, лауреат премий, конкурсы
  студентов — по разделу 9.3.
- **Целевые ИД** (профориентационные мероприятия заказчика, психолого-пед классы) — учёт
  только на целевой квоте, отдельный потолок +5.

### 2.2. Чистая логика — `scraper/abitur/calculator.py`

Чистые функции без сети и без LLM, полностью юнит-тестируемые:

- вход: уровень, признак пед-направления, флаг целевой квоты, множество выбранных
  достижений (для спорта — одно; для волонтёрства — часы и направленность);
- правила: «один вид спорта» (берётся максимум), ГТО однократно, волонтёрство — одна
  максимальная ступень;
- **потолки (раздел 9.4):** общие ИД суммарно — **не более 10**; на целевой квоте — общие
  до 10 **плюс** целевые до 5 = **не более 15**;
- выход: разбивка (что сколько дало) + итог после применения потолка + предупреждение, если
  «сырая» сумма превышала потолок.

### 2.3. Диалог калькулятора в боте

Команда `/bally`. Пошаговый диалог на inline-кнопках:
1. Уровень: БВО/бакалавриат vs СПВО/магистратура.
2. Направление педагогическое (44.xx)? да/нет (влияет на волонтёрство).
3. Целевая квота? да/нет (влияет на потолок).
4. Достижения: набор кнопок-тумблеров (медаль/отличие, ГТО, спортразряд, олимпиада,
   ДО искусства/спорта, СВО, именные конкурсы…); для волонтёрства — ввод часов числом.
5. «Посчитать» → разбивка + итог с учётом потолка + дисклеймер: «предварительно; точный
   учёт — приёмной комиссией по подтверждающим документам» + ссылка на Приложение 7.

**Состояние диалога:** in-memory `dict[chat_id → CalcSession]` (шаг + накопленный выбор).
Эфемерно: теряется при часовом рестарте воркфлоу — приемлемо для короткого расчёта;
сессии с TTL/очисткой по неактивности. Состояние не персистится намеренно.

## Изменения в боте (`scraper/telegram_bot.py`)

- **Убрать** ветку расписания/кодов групп и обращения к `meta/groups.json` из этого бота.
- `route(text|callback) -> intent`: `/start`,`/help`,`/abitur` (меню тем), `/bally`
  (калькулятор), FAQ-кнопка темы, свободный вопрос → AI, шаг калькулятора (callback).
- Разрешить `callback_query` в `getUpdates` (`allowed_updates='["message","callback_query"]"`),
  обрабатывать inline-кнопки (меню тем и калькулятор).
- Маршрутизация/ответы кнопок/диалог калькулятора — чистые функции для юнит-тестов без сети.

## AI-ответ на свободный вопрос — `scraper/abitur/llm.py`

- Один `client.messages.create` (Anthropic SDK, Python). **Модель `claude-haiku-4-5`.**
- **Без** `output_config.effort` (Haiku 4.5 не поддерживает — вернёт ошибку) и без extended
  thinking. Обычный `system` + один `user`.
- `system` = строгая anti-hallucination-инструкция + весь `knowledge.md`, на последнем блоке
  `cache_control: {"type": "ephemeral"}`.
- `max_tokens` ~512. Парсинг `response.content` (блок `text`).
- **Системный промпт:** отвечать ТОЛЬКО по KB; НЕ выдумывать даты/числа/баллы/перечни; если
  вне KB → контакты приёмки + релевантная официальная ссылка + честное «уточните в приёмной
  комиссии»; всегда добавлять ссылку; кратко, по-русски; вопросы про точный расчёт баллов →
  направлять в `/bally`.
- Ошибки SDK (`RateLimitError`, `APIStatusError`, `APIConnectionError`) → дружелюбный фолбэк
  с контактами приёмки, бот не падает.

## Деплой / секреты

- Новый секрет `ANTHROPIC_API_KEY`, проброс в `bot-poll.yml`.
- **Деградация без ключа:** AI-ветка свободных вопросов отключается; FAQ-кнопки и
  **калькулятор работают** (они детерминированы и не зависят от API). Свободный вопрос без
  ключа → «спросите кнопками /abitur, посчитайте баллы /bally или у приёмной комиссии».
- Guard'ы: лимит длины сообщения; простой in-memory rate-limit на `chat_id`.

## Тесты

- `scraper/abitur/calculator.py` — таблица юнит-кейсов: спорт «один вид», ГТО однократно,
  все ступени волонтёрства по уровням и пед/не-пед, потолок 10, целевая квота 10+5=15,
  предупреждение о превышении.
- `route()` и ответы FAQ-кнопок — без сети.
- Диалог калькулятора — переходы шагов и сборка итогового вызова `calculator`.
- LLM-ветка — с моком `messages.create`: проверка сборки `system` (KB присутствует,
  anti-hallucination, `cache_control`), обработки ошибок (фолбэк с контактами).
- Деградация без `ANTHROPIC_API_KEY`.
- Расширить `--selftest` сценариями выше.

## Риски и смягчения

- **Неверные цифры баллов** (чувствительно) → калькулятор детерминирован, цифры в коде из
  первоисточника, покрыт тестами; LLM к арифметике не допущен; явный дисклеймер «предв.,
  точно — приёмной комиссией».
- **Галлюцинации в FAQ** → заземлённый промпт + KB фиксирует ловушки; вне KB → контакты.
- **Расходы на API** → Haiku 4.5 + prompt caching + детерминированные кнопки/калькулятор +
  rate-limit.
- **Устаревание правил кампании** → KB.md и `achievements` версионируются, с датой
  актуальности; обновляются правкой файлов; даты приказов зафиксированы.
- **Потеря состояния калькулятора при рестарте** → диалог короткий; сессии эфемерны, с TTL;
  поведение задокументировано.
- **Сбой/отсутствие API** → graceful degradation, бот не падает.

## Критерии готовности

- Бот не содержит логики расписания; парсеры/данные расписания в репо сохранены.
- `/abitur` показывает меню тем; кнопки дают корректные факты + ссылки из KB.
- Свободный вопрос → заземлённый ответ со ссылкой; вне KB → контакты без выдумок.
- `/bally` корректно считает доп. баллы по сложным правилам (волонтёрство по уровням/пед,
  «один вид спорта», потолок 10/15), с разбивкой и дисклеймером.
- Без `ANTHROPIC_API_KEY` бот зелёный; кнопки и калькулятор работают.
- Юнит-тесты и `--selftest` проходят.
