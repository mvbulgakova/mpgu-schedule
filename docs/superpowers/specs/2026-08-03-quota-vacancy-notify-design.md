# Возврат вакантных квотных/БВИ мест в общий конкурс — дизайн

Дата: 2026-08-03. Статус: утверждён к реализации (согласовано с @soldat_olovyanniy).

## Задача

3 августа подписан приказ о зачислении по приоритетному этапу (особая/целевая/
отдельная квоты, БВИ). По правилам приёма незанятые места по этим категориям
должны вернуться в общий конкурс — но на epk25 КЦП общих списков это пока не
отражает (проверено вручную: `Контрольные цифры приёма` списка 000000700 не
менялось несколько обновлений подряд, хотя в квотных списках-соседях уже видно
реальное `Зачислено`, включая вакансии, например отдельная квота 7 из 9).

Хочется не просто ждать, пока epk25 досчитает, а вручную прикинуть и
предупредить подписчиков: «сейчас вы на такой-то позиции, по квотам есть
незанятые места, которые должны добавить — после этого ориентировочно вы
будете на такой-то».

## Область (scope)

1. Распарсить и сохранить новые поля со страниц epk25 (`Мест для зачисления`,
   `Зачислено`, `Дата и время обновления`) — фундамент для всего остального.
2. Отчёт по всему каталогу: где есть незанятые квотные места, годный для
   ручного просмотра — по нему решаем, куда слать уведомление.
3. Текст предварительного уведомления на список.
4. Механизм отправки конкретному списку.

## Не входит (non-goals)

- Автоматическая/регулярная рассылка — только по разовому запросу.
- Замена существующей логики `places`/`general_seats`/`quota_seats` — новые
  поля добавляются только как доп. сигнал, не меняют текущий расчёт мест.
- Нотификация тем, кто не подписан на конкретный список через `/follow`.

## 1. Новые поля epk25 → `build_lists_index.py`

По аналогии с `_KCP_RE`/`_VID_RE`/`_UNIT_RE`:

- `Мест для зачисления: N` → `seats_open`
- `Зачислено: N` → `enrolled`
- `Дата и время обновления: DD.MM.YYYY. HH:MM` → `page_updated_at` (ISO-строка)

Пишутся в `m[...]` при наличии на странице, как остальные необязательные
поля. Не участвуют в текущих формулах `places`/`general_seats`/`quota_seats`.

## 2. Отчёт по вакантным квотным местам

Новый файл `scraper/abitur/quota_vacancy.py` (чистая логика) +
`scraper/report_quota_vacancies.py` (CLI, читает `lists_meta.json`, печатает
таблицу) — я запускаю сама в чате по запросу, отчёт read-only, без секретов.

Алгоритм:
- Группируем квотные списки (`m["quota"] is True`) по
  `(direction, form, unit)` — та же связка, что уже используется в
  `quota_by_key` для расчёта `quota_seats`.
- Для каждой группы: если у **всех** квотных списков группы известны и
  `kcp_epk`, и `enrolled` — `vacant_i = kcp_epk_i - enrolled_i`,
  `vacant_group = sum(max(vacant_i, 0))`. Если хотя бы у одного списка группы
  `enrolled` (или `kcp_epk`) неизвестен — группа помечается «неизвестно» и
  **не** участвует в отчёте (та же дисциплина, что уже спасла от ложного нуля
  в Анапском филиале — частичные данные хуже, чем открытое «не знаем»).
- В отчёт попадают только группы с `vacant_group > 0`, привязанные к своему
  общему списку (`main_kcp=True` в той же связке `direction+form+unit`).

Формат строки отчёта: направление, форма, подразделение, код общего списка,
текущий КЦП, `vacant_group`, разбивка по видам квот (особая/целевая/отдельная)
с `kcp_epk`/`enrolled` каждой.

## 3. Текст уведомления

На каждого подписчика общего списка, с его последней известной позицией
(`SUBS[chat]["last"][list_code]`):

```
Предварительно: сейчас вы примерно {pos}-е из {kcp} (бюджет,
«{direction}», {form}). По квотам этого направления пока есть незанятые
места (~{vacant}) — по правилам они должны перейти в общий конкурс, но
ещё не добавлены. Если добавят, ориентировочно вы будете ~{pos}-е из
~{kcp + vacant}.

Это предварительная прикидка по открытым данным, а не официальная
информация — точная позиция обновится в живом списке. Следите:
/spisok {code}
```

Если у подписчика нет сохранённой позиции по этому списку (не было ни
одного `/follow`-снимка) — такой подписчик пропускается молча (лог: сколько
пропущено).

## 4. Механизм отправки

Новый `.github/workflows/quota-notify.yml`, `workflow_dispatch` с одним
полем ввода `list_code` — по образцу ручного запуска `deploy-bot.yml`:

- checkout `main`;
- restore `subs.json` из кэша `bot-state-*` (тот же префикс, что использует
  `bot-poll.yml`) — актуальность до последнего цикла бота (часовой), этого
  достаточно для предварительной оценки;
- запускает `scraper/notify_quota_seats.py --code <list_code>` с секретом
  `BOT_TOKEN`; скрипт:
  - подтягивает свежий `lists_meta.json` из ветки `data`;
  - пересчитывает `vacant_group` для группы этого списка (`quota_vacancy.py`,
    та же функция, что и в отчёте);
  - если `vacant_group` неизвестен или ≤ 0 — завершается с сообщением об
    этом в лог, ничего не шлёт;
  - иначе находит в `subs.json` всех подписчиков с `list_code` в `last`,
    шлёт каждому сообщение из п.3 через `sendMessage`, пауза 0.1с между
    отправками (как в существующем `/broadcast`);
  - в конце лога: сколько отправлено, сколько пропущено (нет позиции), был
    ли `vacant_group` пересчитан заново на момент отправки (может отличаться
    от отчёта, если данные успели обновиться).

Ты запускаешь этот workflow вручную (вкладка Actions → Quota Notify → Run
workflow, код списка) — токен бота и подписчики существуют только внутри
Actions, я не могу отправить это сама из чата.

## Изоляция компонентов

- `scraper/abitur/quota_vacancy.py` — чистая функция группировки/расчёта
  вакансий, без сети и файлов на входе (только уже распарсенный
  `lists_meta`). Юнит-тестируема отдельно.
- `scraper/report_quota_vacancies.py` — тонкий CLI поверх неё, read-only.
- `scraper/notify_quota_seats.py` — тонкий CLI поверх неё же + отправка,
  требует `BOT_TOKEN`/`SUBS_PATH`, живёт только в Actions.
- `build_lists_index.py` — только добавляет три новых поля, не трогает
  существующие формулы мест.

## Тестирование

- `quota_vacancy`: группа с полными данными → верный `vacant_group`; группа
  с хотя бы одним неизвестным `enrolled`/`kcp_epk` → группа исключена
  целиком (не даёт заниженного/ложного числа); группа без вакансий
  (`vacant_group == 0`) не попадает в отчёт.
- `report_quota_vacancies`: печатает только группы с `vacant_group > 0`.
- `notify_quota_seats`: строит корректный текст на позицию/КЦП/vacant;
  подписчик без сохранённой позиции — пропущен, не падает; `vacant_group`
  неизвестен/≤0 — ничего не отправляет и явно логирует причину.
- `build_lists_index`: новые поля (`seats_open`/`enrolled`/`page_updated_at`)
  пишутся при наличии на странице и отсутствуют, если поля нет в HTML;
  существующие `places`/`general_seats`/`quota_seats` не меняются.

## Риски

- **Двойной источник неопределённости** (частичные квотные данные +
  задержка кэша `subs.json` до часа) — снимается тем же принципом, что и
  везде в проекте: при любой неполноте данных — открытое «не знаем», не
  занижаем и не завышаем.
- **Сообщение может быстро устареть**, если epk25 досчитает КЦП раньше, чем
  подписчик его прочитает — явная оговорка «предварительная прикидка,
  следите за списком» в тексте это покрывает.
- **Ручной триггер** (нет API-доступа на `workflow_dispatch`) — сознательно
  принято: секреты и подписчики не должны быть доступны мне напрямую.
