# Runbook — бот «Абитуриент МПГУ» (@priem_mpgu_bot)

Инструкция на случай «бот сломался / меня нет». Всё, что нужно, чтобы подхватить
проект без автора.

## Что это и где крутится

- Telegram-бот на long-polling, БЕЗ отдельного хостинга: его гоняет GitHub
  Actions (`.github/workflows/bot-poll.yml`). Один запуск живёт ~5.5 часов,
  затем крон запускает следующий. Код берётся с ветки `main`.
- Данные конкурсных списков лежат в ветке `data` (жёсткий отдельный воркфлоу
  `fetch-lists.yml` периодически обходит epk25.mpgu.su и коммитит туда индекс).
  Бот читает их через `raw.githubusercontent` (+ jsDelivr как фолбэк).
- Кроны читаются с ДЕФОЛТНОЙ ветки (`claude/migrate-mpgu-schedule-jj5gV`).
  Правки воркфлоу нужно пушить и туда, и в `main`.

## Секреты (GitHub → Settings → Secrets and variables → Actions)

| Имя | Что это | Где взять / как обновить |
|-----|---------|--------------------------|
| `BOT_TOKEN` | токен Telegram-бота | @BotFather → `/token` → выбрать @priem_mpgu_bot |
| `ANTHROPIC_API_KEY` | ключ Anthropic API (AI-ответы) | console.anthropic.com → API keys |
| `ADMIN_CHAT_ID` | твой chat id (для `/export`, `/fb_stats`) | напиши боту `/myid`, число — в секрет |

Без `ANTHROPIC_API_KEY` бот работает, но свободные вопросы и `/vybor` отвечают
заглушкой. Без `ADMIN_CHAT_ID` не работают только админ-команды.

## «Бот молчит» — дерево диагностики

1. **Идёт ли ран?** Actions → «Telegram Bot (polling)». Если нет активного —
   планировщик GitHub задержал крон (обычное дело). Нажми **Run workflow**
   вручную — оживёт за минуту. Раны длинные (5.5 ч) как раз чтобы дыр было меньше.
2. **Ран идёт, но бот не отвечает на свободные вопросы?** Открой лог шага
   «Run bot», ищи строку `llm error: ...`:
   - `credit balance is too low` → кончились кредиты Anthropic, пополни
     console.anthropic.com (Plans & Billing). Включи auto-reload.
   - `authentication_error` → протух ключ, перевыпусти и обнови секрет.
   - Детерминированные команды (`/spisok`, `/bally`, `/sroki`) при этом работают.
3. **Не отвечает вообще ни на что?** Скорее всего конфликт вебхука (если кто-то
   поднял второго бота на том же токене). Бот сам делает `deleteWebhook` на
   старте — просто перезапусти ран.
4. **`/spisok` пишет «код не найден» для реальных кодов?** Смотри следующий раздел.

## Данные конкурсных списков сломались

- Проверь свежесть: воркфлоу «Data Freshness Watchdog» открывает issue, если
  индекс не обновлялся ≥8 часов. Или руками: открой
  `https://raw.githubusercontent.com/mvbulgakova/mpgu-schedule/data/admissions/lists_meta.json`
  → поле `updated_at`.
- Запусти «Fetch Competitive Lists» вручную (Actions → Run workflow).
- В логе смотри строку `покрытие мест: N/M` и `stats=`. Если `ОТМЕНА публикации`
  — обход был неполный (сетевой сбой), данные НЕ перезаписаны, старые остались.
  Повтори ран; при упорной блокировке на легитимном сокращении — `FORCE_PUBLISH=1`.
- `⚠️ НИЗКОЕ ПОКРЫТИЕ мест` → сломался матчинг программ (изменились названия/КЦП);
  см. `programs_2026.json` и раздел ниже.

## Как обновить код / передеплоить

- Правки кода → пуш в `main` (бот берёт код оттуда). Подхватится при следующем
  ране; чтобы сразу — отмени текущий ран, очередь стартует новый.
- Правки воркфлоу (`.github/workflows/*`) → пуш и в `main`, и в дефолтную ветку.
- Тесты: `python -m pytest scraper/tests/ -q` (должно быть всё зелёное).
- Ред-тим и синтетика: `python -m scraper.redteam_abitur --det`,
  `python -m scraper.qagen_abitur --n 8` (нужен ANTHROPIC_API_KEY).
